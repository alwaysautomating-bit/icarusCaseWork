# Project

Name: Icarus Casework

Started: 08-13-2026

Status: Rev testimony URL intake implemented and verified end to end on the local Supabase stack

## Purpose

Build a source-grounded case-reconstruction workspace for true-crime researchers and long-form content creators. Icarus Casework preserves originals, separates attributed claims from reviewed events, maintains provenance and contradiction, synchronizes longitudinal timelines, compares explicit competing accounts, and produces versioned narrative research packets with sentence-level citations.

## Problem

Case research commonly collapses statements, observations, repeated reporting, creator interpretation, and later narrative into a single apparent record. Researchers need a defensible way to see who claimed what, from which source, when it entered the record, what independently supports or contradicts it, and what remains unknown.

## Features

- Case rooms with public-record cutoff dates and evidence snapshots
- Immutable heterogeneous source ingestion and exact citations
- Attributed claim extraction with human review
- Entity aliases, provenance roles, and claim lineage
- Reviewed events and synchronized 90-day, 30-day, and incident-window timelines
- Contradiction, dependency, and missing-interval views
- Constrained competing-account feasibility testing
- Cited narrative builder and versioned research-packet export
- Durable entities, reversible aliases, and explicit artifact provenance roles
- Claim genealogy that distinguishes repetition from independent origin
- Unresolved contradiction registry and append-only authority log
- Synchronized 90-day, 30-day, and incident-window projections
- Saved bounded research views
- Evidence-backed terminal contradiction dispositions
- Active saved-view filtering across timeline lanes and contradiction visibility
- Page, timestamp, spreadsheet-range, image-region, and extracted-text citation locators
- Immutable object-storage boundary with local and private Vercel Blob adapters

## Architecture

Current shape: Next.js App Router -> Supabase cookie authentication -> authenticated Server Action -> SSRF-safe URL capture and immutable object storage -> Rev testimony parser -> security-invoker Supabase RPC -> PostgreSQL evidence graph protected by case membership and RLS -> provenance inspection and human review UI. Evidence payloads use checksum-addressed local storage until private Blob credentials are configured.

The implemented intake persists Evidence Lane independently of artifact format, rejects reconciliation and verification fields, treats extraction confidence as extraction metadata only, and reuses an exact-checksum artifact without duplicating segments or claims. A per-owner default-workspace key prevents concurrent first loads from creating duplicate cases.

Local development uses the Supabase Docker stack and therefore requires Docker Desktop. The prior PGlite implementation remains an isolated reference adapter, not the active application runtime.

Deployment target: Supabase for PostgreSQL and authentication, with Neon as a documented fallback and Blob-compatible storage for artifacts/exports. Authentication order is Google, Apple, then magic links; Clerk is prohibited. Firebase requires a concrete documented reason. All database changes use controlled migrations; Prisma, if introduced, must use `prisma migrate deploy` rather than production `db push`.
